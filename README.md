# www.jpilot.org

The J-Pilot website. Plain static HTML, generated by a small Python script and
served by GitHub Pages from the `gh-pages` branch.

There is no Jekyll, no npm, and nothing to install: `src/build.py` uses only the
Python 3 standard library. A `.nojekyll` file at the root tells GitHub Pages to
serve the files exactly as committed.

## Building

```sh
python3 src/build.py                 # write the pages into the repo root
python3 src/tools/check_links.py .   # then check the result
```

`--out DIR` builds somewhere else instead, which is the safe way to preview:

```sh
python3 src/build.py --out _site --serve
```

That serves it on <http://localhost:8000/>. An out-of-tree build copies the
screenshots, manuals, icons and package archive across as well, skipping files
that have not changed.

## Layout

```
src/
  build.py              the whole build, ~250 lines
  templates/base.html   <head>, nav and footer -- the single source of truth
  pages/*.html          one fragment per page; metadata in a leading comment
  static/site.css       hand-written; the display font is inlined at build time
  static/site.js        copy buttons, theme toggle, screenshot viewer
  static/img/           the hero photo and the application screenshots
  static/fonts/         the subsetted display font, and its licence
  tools/                see below
```

Everything else at the root is content the build does not generate:
`documentation/` holds the manuals and their images, `packages/` the older
`.deb` files the download page links, and `CNAME` the custom domain.

## Editing

Pages are HTML fragments under `src/pages/`, each with a metadata header:

```html
<!--
title: Download
nav: Download
description: ...
-->
```

Values like `{{version}}`, `{{pilot_link}}` and `{{releases}}` come from the
`SITE` dictionary at the top of `src/build.py`. Use those rather than writing a
version number into a page, so a release means editing one line.

The nav is built from the page order in `PAGES`, also in `build.py`.

## Tools

| Script | Needs | When to run it |
| --- | --- | --- |
| `tools/check_links.py` | nothing | After every build. `--external` also fetches outbound links. |
| `tools/prepare_palm.py` | Pillow | Only to replace the hero photo. |
| `tools/subset_font.py` | fonttools | Only to change the display font. |
| `tools/demo_data.py` | nothing | To regenerate the invented records used for screenshots. |

The last three write files that are committed, so they are not part of a normal
build.

`check_links.py` is worth running with `--external` before a release. It checks
more than status codes: several links here have returned HTTP 200 while serving
an error page, which is how a package page reads after the package is removed
from a distribution.
